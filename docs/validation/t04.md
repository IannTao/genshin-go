# T04 验证记录

任务为 [#5 独立管理游戏 UID 与验证账号归属](https://github.com/IannTao/genshin-go/issues/5)。

## 实际结果

- Windows 原生窗口使用独立的 `LOCALAPPDATA`。未登录时创建两个 UID 数据空间，切回第一个后重新启动进程。第二次打开恢复第一个为当前 UID，同时仍可选择另一个 UID，账号保持未授权。
- Windows SQLite 和 DPAPI 测试使用临时数据库，覆盖版本迁移、不同 UID 的历史数据保留、Cookie 加密与解密、异账号及写入失败时保留原凭据。
- NSH 隔离交互测试通过替换环境服务控制归属查询和保存，验证首次查询失败、已验证的 UID 和手工空间独立、同账号续期与续期失败。联网查询能力另行实测。
- 完整 Windows 检查通过，包括 Rust 格式、Clippy、Issue 同步脚本离线检查、根目录与隔离夹具的 `nsh check`。根目录 `nsh test` 通过 8 项，4 项需特定网络或授权条件的测试由默认套件跳过。隔离夹具 `nsh test` 通过 20 项。
- 使用不含 Cookie 的请求访问米游社国服角色绑定查询，服务返回 HTTP 200 和业务码 `-100`。Windows Rust 客户端使用合成的无效 Cookie 也收到 `-100`，并返回归属查询失败。带真实授权的 UID 查询仍需用户在 Windows 窗口用米游社扫码确认。[UIGF 接口参考](https://uigf.org/zh/mihoyo-api-collection/hoyolab/user/game_account_info.html)

## 重跑验证

在 Windows 上从仓库根目录运行 `./scripts/check-windows.ps1`。运行 `./docs/validation/t02-windows-live.ps1` 可在独立目录验证真实扫码、重启后显示已验证 UID，以及用 DPAPI 恢复的 Cookie 仍能查询到同一 UID。

## SQLite 结构检查

在 Windows 上用 PowerShell 7.2 或更新版本运行以下命令。脚本使用系统自带的 SQLite 库，以只读方式打开数据库，输出结构版本和各表列名。传入 `-Uid` 可查询指定 UID 是否有数据空间。查询结果只包含版本号、列名和存在状态。

```powershell
./scripts/inspect-sqlite.ps1
./scripts/inspect-sqlite.ps1 -DatabasePath 'C:/temp/launcher.sqlite3' -Uid 123456789
```

默认读取 `%LOCALAPPDATA%/Genshin-Go/launcher.sqlite3`。检查测试库或备份时，用 `-DatabasePath` 指定文件。排查 `no such column: revision` 时，可查看 `UserVersion` 和 `TableColumns.account_authorization`。
