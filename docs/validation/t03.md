原任务要求启动器用已保存账号登录游戏。2026-11-17 实机验证期间，用户确认游戏从启动器普通启动，登录与切换在官方客户端内完成。保存的米游社授权用于后续自动签到和扫码获取祈愿记录。此决定取代原票据的账号启动和双账号切换验收条件。[原 GitHub issue #4](https://github.com/IannTao/genshin-go/issues/4)

普通启动与米游社授权独立。授权数量、续期及旧版升级按单账号规格另行交付。本机数据所有权及 Windows 凭据保护约定继续适用。[单账号规格修订](https://github.com/IannTao/genshin-go/issues/30) · [本机数据与平台边界 ADR](../adr/0001-local-data-and-platform-boundary.md)

## 交付行为

- 普通启动验证游戏目录后，通过 Windows `ShellExecuteW` 以游戏目录为工作目录打开 `YuanShen.exe`。该调用只传入程序路径和工作目录等启动参数，不传米游社 Cookie。客户端负责显示登录流程和管理当前游戏账号。
- 米游社扫码、保存、恢复和重新扫码沿用 T02，独立于普通启动。后续签到和祈愿记录功能分别验收。[T02 验证记录](t02.md)
- 保存及检查授权成功时，界面只报告米游社授权状态。

## 范围修订时的验证

- T01 已在 Windows 验证原生普通启动请求。范围修订时未重测普通启动或客户端内登录。[T01 验证记录](t01.md)
- 范围修订前曾接入独立游戏授权和按账号启动。实机尝试未启动游戏，相关代码和测试已撤回。试验版可能已在本机 DPAPI 文件中保存额外字段，现有程序忽略这些字段。
- 2026-11-18，根目录 `cargo fmt --check` 和两处 `nsh check` 通过。隔离环境 `nsh test` 15 项通过。根目录 `nsh test` 在沙箱内遇到 DPAPI 往返失败，改用当前 Windows 用户权限复跑后 6 项通过，2 项实时测试按设计跳过。
