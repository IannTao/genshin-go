# T02 验证记录

任务：[扫码添加并保存米哈游账号](https://github.com/IannTao/genshin-go/issues/3)。

## 当前实现

启动器通过 UIGF Rust SDK 创建 App 二维码并轮询。用户确认后，启动器用临时 SToken 换取 LToken 和 CookieToken，核对账号标识，再将授权通过当前 Windows 用户的 DPAPI 加密保存。检查授权时，SDK 调用 `verifyLtoken` 和 `verifyCookieToken`，两个接口均返回业务码 0 时显示米游社授权有效。[SDK App 实机结果](t03.md#sdk-app-扫码实机验收)

## 重跑验证

在 Windows 上使用 PowerShell 7.2 或更新版本，从仓库根目录运行：

- `./docs/validation/t02-probe.ps1` 复用启动器的 Rust 实时测试，创建未确认的 SDK 二维码，并断言首次轮询为等待扫码。测试输出通过或失败。
- `./docs/validation/t02-windows-live.ps1` 使用新的独立 `LOCALAPPDATA` 打开启动器。请在二维码出现后两分钟内用米游社扫码并确认。脚本等待界面显示已保存，再打开一个新窗口断言账号已恢复，最后运行 DPAPI 恢复和两项在线授权检查。脚本打印并保留隔离目录，便于失败后复查。

## 旧版 Web 授权检查记录

“检查授权”向 `passport-api.miyoushe.com` 的 `/account/ma-cn-session/web/verifyLtoken` 和 `/account/ma-cn-session/web/verifyCookieToken` 发起 POST。两个接口均返回 `0` 时显示授权有效。连接失败时显示网络错误，服务返回非零状态码时提示暂时无法验证。用户可以重试或重新扫码。请求禁止重定向。[米哈游官方网页 SDK](https://webstatic.mihoyo.com/dora/biz/mihoyo-account-sdk/main.js)。

2026-11-18，旧版 Web 探针和当时的 Rust 客户端的 `cargo test live_unconfirmed_qr -- --ignored` 均通过。创建和首次轮询均返回 `0`，状态为 `Created`。`cargo test live_passport_rejects_invalid_tokens -- --ignored` 使用合成 Cookie 验证两个会话接口均返回 `-100`，客户端归类为暂时无法验证。

同日，经用户授权执行一次 `cargo test live_passport_accepts_saved_authorization -- --ignored`，本机已有授权未通过服务检查。独立实机窗口中，至少一次刚扫码保存的真实授权也收到 `-100`。该返回码目前无法区分凭据失效和服务拒绝请求，已修正误报。扫码保存和双账号重启恢复已通过，真实授权检查的成功路径仍待验证。

本轮根目录和隔离环境的 `cargo fmt --check`、根目录 Clippy 和两处 `nsh check` 均通过。根目录 `nsh test` 通过 6 项，4 项实时或本机授权测试按设计跳过；隔离环境 `nsh test` 通过 16 项，包含二维码创建期间保持扫码状态的回归测试。
