# T02 验证记录

任务：[扫码添加并保存米哈游账号](https://github.com/IannTao/genshin-go/issues/3)。

## 当前实现

米游社扫码使用 passport web API 的 `createQRLogin` 和 `queryQRLoginStatus`。创建与轮询使用相同设备标识；确认后从响应 `Set-Cookie` 取得 `account_id_v2`、`ltoken_v2`、`cookie_token_v2`，并以响应中的 `user_info.mid` 补足 `ltmid_v2`。账号标识与确认回包交叉核对。Cookie 经当前 Windows 用户的 DPAPI 加密，原子保存到 `%LOCALAPPDATA%/Genshin-Go/accounts-passport.dpapi`。旧 GameToken 授权文件不被读取或覆盖。

协议参考：[米游社扫码](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hoyolab.html)、[Cookie 配对要求](https://uigf.org/zh/mihoyo-api-collection/other/authentication.html)、[Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 授权检查

“检查授权”向 `passport-api.miyoushe.com` 的 `/account/ma-cn-session/web/verifyLtoken` 和 `/account/ma-cn-session/web/verifyCookieToken` 发起 POST。两个接口均返回 `0` 时显示授权有效。连接失败时显示网络错误，服务返回非零状态码时提示暂时无法验证。用户可以重试或重新扫码。请求禁止重定向。[米哈游官方网页 SDK](https://webstatic.mihoyo.com/dora/biz/mihoyo-account-sdk/main.js)。

2026-11-18，`docs/validation/t02-probe.ps1` 和当前 Rust 客户端的 `cargo test live_unconfirmed_qr -- --ignored` 均通过。创建和首次轮询均返回 `0`，状态为 `Created`。`cargo test live_passport_rejects_invalid_tokens -- --ignored` 使用合成 Cookie 验证两个会话接口均返回 `-100`，客户端归类为暂时无法验证。

同日，经用户授权执行一次 `cargo test live_passport_accepts_saved_authorization -- --ignored`，本机已有授权未通过服务检查。独立实机窗口中，至少一次刚扫码保存的真实授权也收到 `-100`。该返回码目前无法区分凭据失效和服务拒绝请求，已修正误报。扫码保存和双账号重启恢复已通过，真实授权检查的成功路径仍待验证。

本轮根目录和隔离环境的 `cargo fmt --check`、根目录 Clippy 和两处 `nsh check` 均通过。根目录 `nsh test` 通过 6 项，4 项实时或本机授权测试按设计跳过；隔离环境 `nsh test` 通过 16 项，包含二维码创建期间保持扫码状态的回归测试。

最初曾试用 GameToken 扫码接口，用户确认时返回 `-3503`。按用户指出的 passport API 修正后，以上真实扫码确认已成功；旧接口结果不代表当前流程。
