# T02 验证记录

任务：[扫码添加并保存米哈游账号](https://github.com/IannTao/genshin-go/issues/3)。

## 当前实现

米游社扫码使用 passport web API 的 `createQRLogin` 和 `queryQRLoginStatus`。创建与轮询使用相同设备标识；确认后从响应 `Set-Cookie` 取得 `account_id_v2`、`ltoken_v2`、`cookie_token_v2`，并以响应中的 `user_info.mid` 补足 `ltmid_v2`。账号标识与确认回包交叉核对。Cookie 经当前 Windows 用户的 DPAPI 加密，原子保存到 `%LOCALAPPDATA%/Genshin-Go/accounts-passport.dpapi`。旧 GameToken 授权文件不被读取或覆盖。

协议参考：[米游社扫码](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hoyolab.html)、[Cookie 配对要求](https://uigf.org/zh/mihoyo-api-collection/other/authentication.html)、[Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。

## 实际验收

- 2026-11-16：未授权的 passport 创建与轮询返回 retcode 0，初始状态为 `Created`。`docs/validation/t02-probe.ps1` 可重复此探测；脚本只输出状态码和二维码域名、路径，不输出 ticket、Cookie 或完整 URL。
- 用户在 Windows 原生窗口用米游社扫码确认，界面显示“授权已保存”。关闭并重开后，账号仍显示。修正 Cookie 配对字段及 MID 校验后，用户再次扫描新二维码，界面再次显示“授权已保存”。
- 当前用户环境中，忽略测试 `restored_passport_authorization_has_paired_cookie_fields` 成功解密已保存授权，验证其中同时包含 `ltoken_v2`、`ltmid_v2` 与 `cookie_token_v2`；测试不输出账号和 Cookie。多账号保存、同账号更新、损坏文件保护另由隔离测试覆盖。
- 实机只使用一个真实米游社账号完成重启恢复；两个不同真实账号的重启恢复尚未实测，隔离交互测试已覆盖这一行为。
- 2026-11-17：`cargo fmt --check`、`cargo clippy --workspace --all-targets -- -D warnings`、根目录与 fixture 的 `nsh check` 均通过；根目录完整 `nsh test` 为 6 通过、2 项实时服务测试按设计跳过；fixture 完整 `nsh test` 为 15 通过。

## 授权检查的限制

“检查授权”目前请求 `getUserGameRolesByCookie`。该接口文档要求 DS 等签名请求头；当前请求尚未补齐，所以真实账号的服务返回 `-100` 不能判定为 Cookie 失效。界面显示“暂时无法验证”，仍允许重新扫码。**已验证扫码确认、保存及恢复；尚未验证真实授权有效性判断。** [接口要求](https://uigf.org/zh/mihoyo-api-collection/hoyolab/user/game_account_info.html)。

最初曾试用 GameToken 扫码接口，用户确认时返回 `-3503`。按用户指出的 passport API 修正后，以上真实扫码确认已成功；旧接口结果不代表当前流程。
