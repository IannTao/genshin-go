## 接口依据

- [UIGF 的 GameToken 扫码协议](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hk4e.html)：国服 `hk4e-sdk.mihoyo.com/hk4e_cn/combo/panda/qrcode/fetch` 创建二维码，`query` 轮询；POST JSON 使用 `app_id: "4"` 和同一个设备标识，轮询另外携带二维码地址中的 ticket。状态为 Init、Scanned、Confirmed，过期码 -106；确认后的 Account payload 中 raw 是包含账号 uid 和 token 的 JSON 字符串。这里的 uid 是米哈游账号标识，不是游戏角色 UID。
- [另一套米游社扫码协议](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hoyolab.html)使用 passport web API 和响应 Cookie，与 GameToken 不等价。本实现选择 GameToken 协议，不拼接两套服务的返回值。
- [UIGF Token 协议原始文档](https://github.com/UIGF-org/mihoyo-api-collect/blob/main/hoyolab/user/token.md)描述 `account/ma-cn-session/app/getTokenByGameToken` 的 POST 请求和 `x-rpc-app_id` 请求头。该调用的成功返回可用于检查所保存 GameToken 是否被接受；返回的额外凭据不保存。不以此证明游戏登录完成。
- [Microsoft DPAPI 文档](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)：使用当前 Windows 用户范围及 UI_FORBIDDEN，不使用 LOCAL_MACHINE。返回内存由 LocalFree 释放。文件先加密、再原子替换，授权文件与普通设置分离。
