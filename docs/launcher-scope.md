# 启动器范围与待确认决策

## 已确认（2026-11-14；账号与游戏边界于 2026-11-17 修订）

- 分六批实现、逐批验收；具体顺序见下文。
- 首发支持 Windows、国服官服；未来支持 Android。
- 启动器的米游社账号授权先仅支持扫码；账号密码与短信验证码登录暂不实现。游戏登录由官方客户端处理。
- 成就支持手动标记与数据导入；背包只读浏览。自动获取数据的方式另行核实，不修改游戏服务器上的成就或物品数量。
- 可选注入模块指定集成 [FufuLauncher.UnlockerIsland](https://github.com/FufuLauncher/FufuLauncher.UnlockerIsland)；接口、能力范围和发布方式待核查与确认。
- 第一批验收：识别已有游戏、普通启动真实游戏、扫码添加并保存多个米游社账号。米游社授权有效时无需再次扫码，失效后重新扫码；启动游戏不选择米游社账号。
- 下载更新作为第二批；注入单独验收。
- 区分米哈游账号和游戏角色，抽卡、成就、背包及养成计划按游戏 UID 归属；无法识别 UID 的导入需用户明确选择归属。
- 数据保存在本机，凭据使用 Windows 凭据保护能力；不建设启动器自有账号体系或云同步服务。
- 签到仅需一个指定账号，取消首期批量签到；打开启动器后检查当天状态并执行尚未完成的签到，提供手动重试。启动器关闭期间不执行。
- Android 未来承担账号、签到和数据查看等伴随功能；Windows 游戏安装管理与指定注入模块仅用于 Windows。
- 游戏账号的登录与切换在官方客户端内完成，启动器不强制结束游戏。
- 移除账号时删除登录凭据，保留各 UID 的历史业务记录；重新添加同一账号后恢复关联。删除历史记录为独立操作，明确列出将删除的 UID。
- 自动查找已有游戏目录并支持手动选择；多个有效目录由用户选择默认目录。路径失效时提示重新选择；没有游戏时第一批提示先安装，第二批提供下载。
- 第一期支持业务记录备份与导入，明确包括抽卡、成就和养成记录；备份不携带登录授权，换电脑后重新扫码。
- 启动器跨天保持打开时，按各签到服务的日期边界检查并执行新一天签到；电脑休眠恢复后检查。游戏内切换账号不改变指定签到账号。
- 下载、更新包下载与预下载支持暂停、继续、重启后断点续传；关闭时保存进度，重新打开后由用户手动继续未完成任务。
- 游戏运行期间可以下载更新包和预下载资源；安装更新或修复文件须等游戏退出。预下载完成只保存资源，到可更新时提示安装；安装或修复期间阻止启动对应游戏目录。
- 导入写入前显示新增、重复和冲突数量，自动备份现有数据。抽卡去重；成就合并保留任一来源的已完成状态；养成计划冲突由用户选择保留版本。
- 养成计算由用户填写当前状态与目标状态，角色包含等级、突破和天赋，武器包含等级与突破；计算材料需求并可扣除库存。库存可手填或使用已导入背包记录，显示记录时间。
- 项目公开源码并提供构建产物下载；最终许可证待复用边界核实后确定。
- 插件商店管理明确目录中的游戏外部工具、模组或注入组件，支持浏览、安装、更新和卸载；首期不提供第三方扩展启动器页面的开发框架。类别与兼容格式按实际来源核实。
- 注入默认关闭，由用户主动启用；保留独立普通启动入口。注入失败明确报告，由用户选择是否普通启动，不静默回退。
- 抽卡支持 UIGF v4.0–v4.2 原神祈愿记录导入、统一导出 v4.2；成就支持 UIAF v1.1 导入导出，旧版暂不兼容。规范来源为 [UIGF 组织](https://uigf.org/zh/)；不以参考工具私有格式作为首批兼容目标。文件中其他游戏数据不导入并明确提示；标准格式导出与整体备份分别提供。
- 本期不实现镜像加速。
- 背包纳入整体备份，保留原始采集时间；同一 UID 默认采用较新的完整快照，不叠加数量，恢复旧快照须用户明确选择。
- 本项目维护精选插件目录，不开放任意第三方商店源；每项明确来源、版本与安装位置，逐项核实安装、更新和卸载方式。更新由用户点击执行；首批具体条目待兼容性核查后确认。
- UnlockerIsland 优先集成经过验证的固定版本，维护启动器侧适配，不承诺开发模块内部新功能或持续修复其内部逻辑。升级先验证兼容性，再由用户选择更新；使用构建产物还是源码构建，待接口和发布条件核实后确定。
- 本地数据功能无需登录：可按 UID 导入、查看抽卡和成就、创建养成计划；登录用于需授权的服务。添加账号后，仅关联经验证属于该账号的 UID。
- 签到网络超时有限次数自动重试；登录失效或需人工验证时停止该项并提示处理，其他可执行项继续。各项分别显示成功、已签到、失败或待处理；手动重试只针对未完成项，奖励日历不把失败项显示为已领取。

## 交付批次

1. 已安装游戏识别、普通启动、米游社扫码账号管理。
2. 下载、增量更新、预下载、校验修复。
3. 单账号签到与奖励日历。
4. UIGF 抽卡分析、UIAF 成就、备份迁移。
5. 背包与养成计算器；此批补齐背包备份。
6. 插件商店与 UnlockerIsland 集成。

每批完成真实流程验收后推进下一批。

## 仓库事实

当前源码是 Rust + NSH 计数器骨架，没有启动器业务实现。保持现有 Rust UI 入口；参考项目的功能声明不等同于本项目已实现或已验证的能力。

2026-11-14 核查：指定的 [UnlockerIsland 仓库](https://github.com/FufuLauncher/FufuLauncher.UnlockerIsland)标示 AGPL-3.0 许可；不能沿用主启动器的许可结论推定该模块的许可。项目已确定公开源码并提供构建产物，具体复用方案与最终许可证仍待确定。

2026-11-14 核查：[UIGF 当前规范](https://uigf.org/zh/standards/uigf.html)为 v4.2，v4 与 v3 及以下存在结构不兼容；规范允许只处理目标游戏的数据，认证要求同时实现导入和导出。官网导航列出 UIAF v1.1，但其详情页本轮两次读取超时，字段细节尚未完成核查。

## 扫码授权核查（2026-11-14）

用户指定参考 [米游社扫码登录](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hoyolab.html)。该文档描述国服 `createQRLogin` 生成二维码与 ticket，`queryQRLoginStatus` 查询状态；需要应用及设备标识请求头。确认后从响应的全部 `Set-Cookie` 提取账号标识、LToken V2 和 Cookie Token，不能从示例中始终为空的 `tokens` 数组读取凭据。状态包含未扫描、已扫描、已确认，并定义过期和取消错误。

相邻的 [GameToken 扫码文档](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hk4e.html)描述另一套国服 `qrcode/fetch` 与 `qrcode/query` 接口；确认后解析 `payload.raw` 内的 JSON，取得账号标识和 GameToken。这里的账号标识不能直接当作游戏角色 UID。

这两份文档说明不同授权结果。2026-11-17 用户澄清，启动器只普通启动游戏，游戏登录由客户端处理。米游社扫码授权留给后续签到和扫码获取祈愿记录。此决定取代已发布第一期规格、T03 和 T26 中要求启动器指定或切换游戏账号的条款。[T03 范围修订与验证记录](validation/t03.md)
