# 使用 SQLite 保存本机账号和游戏角色数据

账号授权需要可靠迁移，按 UID 管理的业务记录也需要独立更新与合并，因此采用带版本迁移的本机 SQLite 数据库。Windows 使用当前用户的 DPAPI 加密 Cookie 后再写入数据库，可迁移的业务备份排除凭据。游戏安装目录继续保存在 `settings.json`。

首次扫码须查询并验证唯一游戏 UID 才能保存账号。查询失败时向用户报错；重新扫码失败时保留原 UID 和凭据。

首批交付数据库初始化、版本迁移及已有账号迁移。升级时从 `accounts-passport.dpapi` 读取全部账号并验证各自 UID，整批写入并确认授权可读后再启用新库、清理旧文件。任一查询、写入或读取验证失败时，整批迁移报错，旧文件保留。中断或失败后可整批重试，避免重复账号或丢失授权。

抽卡记录、成就进度、背包快照和养成计划随对应任务建表。材料目录共用，库存数量与采集时间按 UID 保存，同一 UID 的完整快照按采集时间选用，数量不累加。
