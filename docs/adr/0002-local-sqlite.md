# 使用 SQLite 保存本机账号和游戏角色数据

按 UID 管理的业务记录需要独立更新与合并，因此采用带版本迁移的本机 SQLite 数据库。Windows 使用当前用户的 DPAPI 加密 Cookie 后再写入数据库，可迁移的业务备份排除凭据。游戏安装目录继续保存在 `settings.json`。

启动器最多保存一个米游社授权。首次扫码须查询并验证唯一游戏 UID 才能保存账号。查询失败时向用户报错。重新扫码只续期当前账号，扫到其他账号或续期失败时保留原 UID 和凭据。更换账号须先移除当前授权，再扫码添加新账号。各 UID 的历史记录独立保留。

2026-11-18 修订：从多账号版本首次升级到单账号版本时，清除旧版保存的全部米游社授权，包括旧版仅保存一个账号的情况。用户按需重新扫码，新授权在后续启动时正常恢复。原定从 `accounts-passport.dpapi` 逐个迁移账号的流程取消。此次清理仅涉及授权，已有游戏角色和各 UID 的历史记录继续保留。

抽卡记录、成就进度、背包快照和养成计划随对应任务建表。材料目录共用，库存数量与采集时间按 UID 保存，同一 UID 的完整快照按采集时间选用，数量不累加。

UID 业务记录直接或通过所属记录引用 `uid_history(uid)`，外键使用 `ON DELETE CASCADE`，相关 SQLite 连接启用外键约束。启动器在同一事务中删除所选 UID 的历史并恢复其历史入口，以便继续写入。共用数据、UID 数据空间、当前选择和授权独立保存。
