## Problem Statement

启动器目前会保存并恢复多个米游社授权。用户希望打开启动器就能知道签到等服务将使用哪个账号，同时仍能按游戏 UID 查看过去积累的记录。

## Solution

启动器同一时间最多保存一个米游社授权。首次使用时扫码，已授权时可为当前账号续期或移除授权。需要换账号时先移除，再扫码添加。升级到单账号版时清除旧版授权，用户可按需重新扫码。

## User Stories

1. 作为首次使用启动器的用户，我希望可以先普通启动游戏，以便在官方客户端内登录。
2. 作为尚未授权的用户，我希望扫码添加一个米哈游账号，以便使用需要米游社授权的功能。
3. 作为已授权用户，我希望看到当前账号，以便知道签到等服务将使用哪个身份。
4. 作为重新打开启动器的用户，我希望恢复单账号版保存的授权，以便继续使用当前账号。
5. 作为需要续期的用户，我希望用同一账号重新扫码，以便更新它的授权。
6. 作为误用另一个账号扫码的用户，我希望收到账号不一致的提示，并保有原授权，以便用正确的账号重试。
7. 作为扫码被取消、过期或遇到网络错误的用户，我希望原账号和 UID 得到保留，以便稍后继续续期。
8. 作为准备换账号的用户，我希望能先移除当前授权，再扫码添加新账号，以便由自己决定何时更换身份。
9. 作为在旧版只保存一个账号的用户，我希望首次升级后看到扫码入口，以便重新建立授权。
10. 作为在旧版保存多个账号的用户，我希望升级后直接扫码使用所需账号，以便省去从旧列表中挑选的步骤。
11. 作为暂时不想重新授权的用户，我希望升级后仍可按 UID 查看本机记录，以便继续使用已有数据。
12. 作为拥有多个 UID 历史记录的用户，我希望升级、续期和移除授权都保留各 UID 的记录，以便随时查看对应角色的历史。

## Implementation Decisions

- 账号界面提供未授权和已授权两种状态，移除多账号列表和账号选择入口。需要授权的服务使用当前唯一授权。
- 初次授权遵循既有 UID 归属验证规则。续期只接受当前账号，验证和保存成功后才替换凭据。账号不一致、验证失败、写入失败或取消时保留原授权及 UID。
- 单账号限制在本机存储层也须成立，包括同时打开两个启动器的情形。Windows 继续使用当前用户的 DPAPI 保护凭据。
- 从多账号版首次升级时清除全部旧授权，包括只有一条旧授权的情形。升级清理可在中断后重试。后续正常启动恢复新版授权，重复启动或重试升级均须避免误删新授权。
- 授权清理与按 UID 保存的历史数据独立。移除授权之后可以添加不同账号，历史记录继续归属原 UID。

## Testing Decisions

- 沿用已确认的 NSH 根组件交互边界，在应用环境边界替换扫码服务和本机存储。通过用户操作、状态提示和重新打开后的结果断言行为。
- 复用已有扫码确认、取消、过期刷新和续期场景，将多账号并存用例更新为同账号续期、异账号被拒、移除后添加另一账号。验证失败后重启仍恢复原账号。
- 沿用 Windows 隔离存储测试，分别准备含零个、一个、多个授权的旧版数据。验证升级后无授权、各 UID 历史仍可读取，以及再次扫码后连续重启能恢复新授权。覆盖升级中断重试及并发添加账号。
- 使用独立验收目录进行 Windows 实机验证，走通旧版升级、真实扫码、重启恢复和移除后更换账号。记录实际通过项和服务限制，避免记录账号凭据。

## Out of Scope

游戏客户端内的登录和账号切换、手动删除 UID 历史记录、签到和祈愿功能本身的开发，以及在线授权检查接口的排障，均另行处理。

## Further Notes

本规格修订一期规格 #1 的账号范围，取代 #3 的多账号同时保存与恢复、#4 的已保存账号选择，以及 #5 中迁移旧授权的要求。#5 的 UID 归属验证和 #6 的历史记录独立管理继续适用。此前多账号实机验收记录描述的是旧版行为。
