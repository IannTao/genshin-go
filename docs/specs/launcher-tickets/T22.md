## What to build

角色和武器计划可选择同 UID 的背包库存，显示采集时间并计算材料缺口，避免跨 UID 混用。

批次 5；批准的拆分编号 T22。每批完成真实流程验收后再推进下一批；原生阻塞关系仅表示技术前置。

沿用 Rust UI 和领域术语，遵循本机数据所有权与平台边界。首次使用的接口、资源与权限须核实；无法验证时报告具体阻塞，不自动缩减范围。

## Acceptance criteria

- [ ] 角色和武器计划均可选择同 UID 的背包库存，禁止跨 UID 混用。
- [ ] 显示采用快照的采集时间，清楚区分手填库存与导入库存。
- [ ] 材料缺口与库存相符，库存充足时不出现负需求，不修改服务器物品。
- [ ] 通过已确认的 NSH 根组件交互边界验证本票可观察行为；纯逻辑按需补测试，平台或服务实际流程提供真实验证结果。
- [ ] 运行与变更对应的 Rust 格式、NSH 检查及交互测试，交付时记录实际通过项与未完成项。
