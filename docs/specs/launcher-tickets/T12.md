## What to build

核实云游戏签到授权和入口，接入单账号执行流程；明确区分成功、已签到、失败和待处理。

批次 3；批准的拆分编号 T12。每批完成真实流程验收后再推进下一批；原生阻塞关系仅表示技术前置。

沿用 Rust UI 和领域术语，遵循本机数据所有权与平台边界。首次使用的接口、资源与权限须核实；无法验证时报告具体阻塞，不自动缩减范围。

## Acceptance criteria

- [ ] 核实云游戏签到入口及所需授权，明确与已有扫码凭据的关系。
- [ ] 在同一指定账号及触发规则下执行，显示成功、已签到、失败或待处理。
- [ ] 授权不足时明确提示，不伪造成功；云游戏失败不阻止其他可执行项目。
- [ ] 通过已确认的 NSH 根组件交互边界验证本票可观察行为；纯逻辑按需补测试，平台或服务实际流程提供真实验证结果。
- [ ] 运行与变更对应的 Rust 格式、NSH 检查及交互测试，交付时记录实际通过项与未完成项。
