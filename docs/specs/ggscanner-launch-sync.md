## Problem Statement

玩家通过 Windows 启动器进入国服官服原神后，希望在启动器里看到这次实际登录 UID 的成就、已拥有角色、武器和圣遗物。现在「普通启动」只报告 Windows 是否接受了启动请求。玩家仍需另行维护资料，也难以判断某一类记录是今天取得的，还是上次留下的。

## Solution

玩家首次选择已有的 GGScanner.exe、在扫描器中选中原神并开启持续同步。此后每次点击「普通启动」，启动器先准备扫描器，再启动游戏。玩家照常登录和游玩，无需进入特定游戏页面。启动器按实际 UID 将四类数据陆续存入本机，显示每类的结果和时间。一次启动执行一次同步，扫描失败时游戏照常启动。

## User Stories

1. 作为首次使用的玩家，我希望选择已有的 GGScanner 并检查连接，以便在启动游戏前知道设置是否可用。
2. 作为玩家，我希望一次启用后沿用「普通启动」按钮，以便下次登录时自动更新资料。
3. 作为已经打开扫描器的玩家，我希望启动器复用它，以便避免重复开程序。
4. 作为尚未打开扫描器的玩家，我希望启动器在游戏登录前将它准备好，以便捕获本次登录的数据。
5. 作为急于进入游戏的玩家，我希望等待扫描器时可以直接启动，以便扫描器准备过慢时仍能游玩。
6. 作为玩家，我希望扫描失败时看到具体原因和独立的游戏启动结果，以便区分权限、配置和游戏启动问题。
7. 作为管理多个 UID 的玩家，我希望数据写入实际登录的游戏 UID，以便在浏览 A 时也能准确更新 B。
8. 作为首次登录某个 UID 的玩家，我希望启动器自动建立其数据空间，以便免去预先建档和切换资料页的步骤。
9. 作为玩家，我希望每收到一个完整类别就保存一类，以便即使很快退出也能看到已经取得的资料。
10. 作为玩家，我希望看到已拥有角色的等级、突破、命座和天赋，以便核对当前养成情况。
11. 作为玩家，我希望背包保留同名武器和相同面板的多件圣遗物，以便记录与游戏内实际件数相符。
12. 作为玩家，我希望强化、消耗或替换装备后能看到新库存，并可恢复上一份该类记录，以便核查意外变化。
13. 作为玩家，我希望随时手动标记或取消完成成就，并由后续完整扫描纠正，以便离线时也能维护进度。
14. 作为玩家，我希望已收到的成就立即显示为完成，以便成就分批到达时也能看到进展。
15. 作为已有 UIAF 记录的玩家，我希望查看已知完成日期及其来源，以便区分实际完成日期和本次同步时间。
16. 作为玩家，我希望知道哪个类别还在等待、上次何时更新，以便区分空库存、本次尚未收到和从未更新。
17. 作为玩家，我希望正常游玩时提示留在启动器内，以便同步不会打断操作。
18. 作为玩家，我希望同步结束后由启动器收起本次专用的扫描器，并保留我自己打开的实例，以便继续原来的操作。
19. 作为换机或清理历史的玩家，我希望四类资料沿用已有 UID 备份、恢复和删除规则，以便管理自己的本地数据。

## Implementation Decisions

- **接入与启动。** 首版兼容性基线为 GGScanner v2026.11.15 的 Windows 抓包版。启用时展示采集方式、管理员权限要求及上游风险说明，保存玩家选择的程序和本机端口，并提供版本提示与连接检查。在现有「普通启动」验证游戏目录后，先复用原神管理服务；服务未运行时尝试启动所选实例。固定版的 `--agent-mode` 会打开 GUI，依赖保存的游戏、持续同步开关和权限，升级兼容性须复验。准备等待有上限，允许「直接启动游戏」。取消提权、端口占用或扫描器不可用时，首页报告扫描失败原因并继续启动游戏。
- **会话与归属。** 通过本机 `GET /continuous` 读取快照，默认端口 8765。启动前若已有结果，记下旧会话，仅接受随后登录产生的新会话。收到 503 时区分“等待初始数据”和采集失败；409 禁用时提示检查配置。校验 GOOD v3 和 `metadata.uid`，以该游戏 UID 建档、入库，保留正在浏览的 UID。米游社授权独立于本次同步。
- **逐类保存。** 同一启动只运行一个同步任务。按 UID 和类别把数据、会话、修订、源数据变更时间及本机接收时间共同提交到 SQLite；重放和过期响应不能重复计数或回退记录。新登录的修订号独立计算。字段缺失、无效或尚未取得完整库存时，保留该类原有库存及时间。四类都确认完整并保存后结束；取消、超时或退出时保留已提交数据。
- **已拥有角色与背包。** 保存角色键、元素形态和养成现状；武器保留等级、突破、精炼、装备归属及锁定状态；圣遗物保留套装、部位、等级、主副词条、装备归属及锁定状态。各类完整列表按 UID 替换，保留重复实例。完整装备列表为空时清零该类库存。武器和圣遗物各保留上一份可恢复快照，养成目标独立于扫描记录。
- **成就完成状态。** 每批已收到的完成 ID 可立即保存。完整性未确认时，只增加本次已观测到的完成项；只有确认列表完整，才能撤销缺席 ID 的完成标记，包括完整空列表。玩家手动修改立即生效。同一次扫描的重复响应保留这次扫描之后的手动修改；下次完整扫描即使内容相同，仍可覆盖两次扫描之间的修改。
- **成就完成时间。** 首版同步完成状态。已有 UIAF 完成日期保留并注明来源，缺少日期时显示「完成时间未知」。快照内容变更和本机接收时间只用于同步信息。GGScanner 今后若提供单项实际完成时间，以它为准。
- **状态与收尾。** 首页独立显示启动结果和扫描失败原因。角色资料显示实际 UID、各类条数、结果和更新时间。其余三类已保存时，在启动器内提示一次等待成就数据，保持游戏焦点；结束时如实显示已更新的类别数。同步完成、玩家取消或游戏退出时，仅向本次专用实例请求正常关闭。玩家原本已打开的扫描器继续运行。
- **数据生命周期。** 快照随对应 UID 历史级联删除。新版本整体备份纳入四类记录，兼容现有 v1 备份，恢复缺少某类记录的旧备份时保留该类已有数据。自动同步在启用后按上述规则保存；手动导入继续使用已有预览与备份流程。

## Testing Decisions

沿用一期已确认的最高测试入口：从 NSH 根组件操作真实「普通启动」、成就和角色资料界面，在现有启动器环境边界控制游戏请求、扫描器生命周期和响应。使用隔离 SQLite，通过页面状态和重新打开后的业务记录验收。现有普通启动交互、分 UID 历史删除、UIAF 往返和整体备份测试为先例。

- [ ] 从扫描器已开与未开两种状态启动，覆盖重复点击、目录失效、取消提权、服务禁用与端口错误。验证游戏启动结果、失败原因及实例关闭归属。
- [ ] 先返回旧会话，再返回实际登录 UID 的新会话。确认旧结果未写入，首次 UID 自动建档，重启后可查看，原浏览 UID 的记录和选择保持正确。
- [ ] 先只返回武器，再返回其余类别；中途退出后重新打开仍能看到武器。覆盖缺失字段、完整空列表、同名多件、消耗装备、恢复上份快照、重复及过期修订。
- [ ] 成就分批到达时验证已收到的 ID 和旧手动标记。再用已确认完整的列表及完整空列表验证覆盖规则；覆盖两次相同扫描之间的手动编辑、UIAF 日期来源与未知日期。仅取得部分成就时，如实报告部分结果。
- [ ] 验证删除某一 UID 历史后旧任务无法回写，其他 UID 独立保留。验证新版备份往返及旧版恢复。运行项目约定的格式、Clippy、NSH 检查和交互测试。
- [ ] 使用固定发行版与 Windows 国服官服客户端实测冷启动、权限请求、正常关闭和不同启动之间的 UID 归属。玩家正常登录，全程无需打开成就页。将真实快照与已知记录对照，记录首次及后续批次、四类数据和任何未验证项。

## Out of Scope

首版限 Windows 国服官服与玩家已有的 GGScanner。整场游戏持续追踪、同次启动中途换号、扫描器分发或自动更新、OCR 自动补录、装备管理写操作、材料采集及养成计算另行规划。首版不要求上游提供逐项成就完成时间。
