# 原神启动器第一期规格

整理日期：2026-11-15。产品范围来源于已确认的 Q1–Q33，测试边界已于 2026-11-15 经用户确认。目标仓库：IannTao/genshin-go；分诊标签：`ready-for-agent`。技术未决事项见 Further Notes。

## Problem Statement

Windows 国服官服玩家需要同时管理多个米哈游账号、游戏安装、签到及角色数据。当前项目只有 Rust + NSH 计数器骨架，没有这些业务能力。玩家需要一个统一的启动器，能够快速切换并真实启动游戏，同时保留可迁移的本地记录，而不是只能展示静态页面或占位结果。

## Solution

提供 Windows 国服官服启动器，沿用 Rust UI，采用本机数据保存与受保护的扫码授权。按六批实现并逐批完成真实流程验收：账号与启动、安装维护、签到、抽卡与成就及备份、背包与养成、插件与可选注入。

账号功能与游戏角色数据分开：米哈游账号代表登录身份，游戏角色以 UID 标识。无需登录即可使用本地记录功能，联网授权仅在相关服务需要时使用。未来 Android 定位为伴随端，不承接 Windows 安装管理与指定注入模块。

## User Stories

1. 作为Windows 国服官服玩家，我希望在同一个启动器管理游戏与账号，以便减少在多个工具之间切换。
2. 作为玩家，我希望自动识别已安装游戏并手动选择目录，以便使用已有安装。
3. 作为拥有多个安装目录的玩家，我希望选择默认游戏目录，以便启动正确的游戏副本。
4. 作为玩家，我希望路径失效时得到重新选择提示，以便修正启动目标。
5. 作为尚未安装游戏的玩家，我希望看到安装指引并在第二批获得下载入口，以便明确如何开始使用。
6. 作为玩家，我希望扫码添加米哈游账号，以便无需在启动器输入密码。
7. 作为玩家，我希望看到二维码等待扫描、等待确认、过期和取消状态，以便知道下一步操作。
8. 作为多账号玩家，我希望保存多个米哈游账号，以便便捷选择游戏身份。
9. 作为玩家，我希望授权有效时无需再次扫码即可切换并启动游戏，以便缩短启动流程。
10. 作为玩家，我希望授权失效时收到重新扫码提示，以便恢复登录。
11. 作为正在游戏的玩家，我希望切换账号前被提示正常退出游戏，以便避免游戏被强制结束。
12. 作为玩家，我希望重启启动器后保留账号及业务记录，以便继续上次的使用。
13. 作为玩家，我希望登录凭据受到 Windows 本机保护，以便妥善保管授权信息。
14. 作为玩家，我希望按游戏 UID 分别保存抽卡、成就、背包和养成计划，以便避免不同角色记录混杂。
15. 作为未登录用户，我希望按 UID 导入记录和创建养成计划，以便独立使用本地数据功能。
16. 作为玩家，我希望添加账号后只关联经验证属于该账号的 UID，以便保持账号归属正确。
17. 作为玩家，我希望移除账号时只移除登录凭据并保留历史记录，以便不因退出授权丢失数据。
18. 作为玩家，我希望重新添加同一账号后恢复历史记录关联，以便继续原有计划。
19. 作为玩家，我希望独立删除历史记录并先看到涉及的 UID，以便明确删除范围。
20. 作为玩家，我希望指定一个账号执行自动签到，以便为固定账号领取签到奖励。
21. 作为玩家，我希望打开启动器时检查并完成当日未完成签到，以便减少重复操作。
22. 作为保持启动器打开的玩家，我希望跨日和休眠恢复时重新检查签到，以便避免错过新一天。
23. 作为多账号玩家，我希望切换游戏账号时保持指定签到账号不变，以便防止签到对象意外改变。
24. 作为玩家，我希望查看社区签到的成功、已签到、失败或待处理，以便了解当天结果。
25. 作为玩家，我希望网络超时后得到有限次重试，以便应对短暂网络故障。
26. 作为玩家，我希望授权失效或需人工验证时得到明确提示，以便恢复社区签到。

## Implementation Decisions

### 已确认的领域与平台约束

- 沿用 Rust + NSH 和 Rust 根组件入口，保持平台条件编译边界；新增依赖前检查现有能力，NSH 依赖与 CLI 版本保持一致。
- 区分米哈游账号、游戏角色、账号切换、移除账号、成就进度和背包仓库。米哈游账号标识不能当作游戏 UID。
- 数据保存在本机；Windows 保护登录凭据，备份不包含授权。移除账号和删除历史记录是不同操作。
- 每个米哈游账号对应唯一游戏 UID。账号和游戏角色数据采用 SQLite，升级与失败处理见[本机存储决策](../adr/0002-local-sqlite.md)。
- 抽卡、成就、背包及养成计划按 UID 归属。未登录记录可独立存在，账号归属通过验证后关联。
- 首发仅 Windows 国服官服。项目公开源码并发布构建产物；最终许可证须在复用边界核实后确定。
- 遵循已记录的本机数据所有权与平台能力边界决策；本期没有启动器自有账号体系和云同步。

### 功能模块及交互约定

- 账号与启动：识别和选择游戏目录，管理扫码状态和授权，保存多账号，在游戏退出后切换并启动。不存在有效安装时，第一批提示先安装，第二批接入下载。
- 安装维护：下载、增量更新、预下载、校验和修复；支持断点续传，重启后等待用户继续。运行中允许下载，更新和修复等待游戏退出；修改期间禁止启动对应安装。
- 社区签到：指定一个账号，启动器打开、跨服务日期边界及休眠恢复时检查；关闭期间不执行。网络超时有限次重试，授权或人工验证问题停止重试并提示用户处理。手动重试仅处理未完成项，奖励日历依据实际结果。
- 抽卡与成就：UIGF v4.0–v4.2 原神祈愿记录导入、v4.2 导出；UIAF v1.1 导入导出。忽略其他游戏数据时明确提示。抽卡按记录去重，成就合并保留任一来源的完成状态；成就支持手动标记。
- 备份迁移：与标准格式交换分开提供。导入前预览新增、重复和冲突数量并备份现有数据；养成计划冲突由用户选择。抽卡、成就、养成和背包数据可迁移，凭据不迁移。
- 背包与养成：背包只读，保留采集时间；同 UID 使用较新的完整快照，不相加，旧快照恢复须明确选择。角色计算覆盖等级、突破、天赋，武器覆盖等级与突破；支持手填或导入库存扣除需求。
- 插件：本项目维护精选目录，明确来源、版本、安装位置；逐项验证安装、手动更新和卸载方法。首批条目需在兼容性核查后确认。
- 注入：集成经过验证的固定版本 UnlockerIsland，默认关闭，普通启动入口独立存在。失败明确报告，不静默回退；兼容性验证后由用户选择升级。仅维护启动器侧适配，不承诺模块内部新功能和持续修复。

### 授权接口依据与未验证边界

- 用户指定的[米游社扫码文档](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hoyolab.html)描述创建二维码、轮询状态及确认后取得响应 Cookie 的流程。
- [GameToken 扫码文档](https://uigf.org/zh/mihoyo-api-collection/hoyolab/login/qrcode_hk4e.html)描述另一套扫码接口及确认后的账号标识和 GameToken 返回值。
- 两种凭据不能直接视为等价；米游社扫码成功不代表游戏登录已完成。客户端登录衔接、凭据转换与真实接口行为尚待验证，第一批验收仍要求真实账号切换与游戏启动。
- UIGF/UIAF 以[组织规范](https://uigf.org/zh/)为准。规范支持版本是已确认目标；UIAF 字段细节尚待核查。
- UnlockerIsland 标示 AGPL-3.0；具体接口、构建运行要求、交付产物和许可复用边界尚待核实。不以主启动器的许可证推断该独立模块的条件。

### 拟议实现组织，尚非既有代码

按账号与启动、安装维护、签到、数据导入导出与统计、背包与养成、插件与注入划分业务职责，避免 UI 直接处理授权凭据或文件修改。这些是业务边界，不要求每项独立为一个 crate，下载库和插件协议随对应任务确定。

已确认在应用入口建立一个可替换的运行环境边界，集中提供网络、时钟、本地存储、凭据保护及 Windows 进程和安装操作。真实环境使用平台适配，测试环境使用可控实现；避免为每个内部函数增加测试接口。具体接口形状待实现时依据 NSH 能力确定。

## Testing Decisions

### 测试边界（已确认）

优先复用现有 NSH 根组件交互入口，以启动应用、点击控件和读取可见状态的方式验证用户流程。现有先例是根组件计数器的无头交互测试，但它尚不覆盖启动器业务。

在上述单一应用环境边界提供可控外部行为，覆盖网络结果、时间推进、安装状态和凭据操作；测试断言可见状态、保存后重新打开的结果及外部操作的语义，不断言内部调用顺序、私有函数或实现结构。仅对格式转换、去重、统计、合并和养成计算等纯逻辑补充 Rust 表驱动或往返测试，不逐层重复同一行为。

### 行为覆盖

- 账号与启动：二维码状态、失效重新扫码、重启后保留账号、切换账号后真实选择目标、运行中阻止切换、失效路径、无安装提示、移除凭据且保留记录。
- 安装维护：下载中断及恢复、重启不自动继续、预下载不立即安装、游戏运行与文件修改互斥、校验发现损坏并修复。不能只断言进度条变化。
- 签到：日期边界、休眠恢复、固定账号、已签到跳过、有限重试、失效或人工验证、手动重试及奖励结果一致性。通过可控时钟测试，不等待真实跨日。
- 数据交换：约定版本的真实结构样例、导入导出往返、去重、跨 UID 隔离、缺少 UID 时归属选择、多游戏文件提示、导入预览与备份、成就合并和计划冲突。未知或损坏格式应有明确结果，不能悄悄丢失记录。
- 背包与养成：快照不累加、较新优先、旧快照明确选择、采集时间保留、角色与武器材料计算及库存扣减。
- 插件与注入：来源及版本展示、用户触发更新、安装和卸载结果、默认普通启动、注入失败不静默回退。
- 凭据与迁移：导出不包含登录授权、换机需重新扫码、移除账号不会删除其历史记录。

### 实机验收与检查

无头测试不能替代 Windows 真实扫码、凭据保护、游戏启动、增量安装和注入的验证。每批在相应环境完成真实流程后才算通过；缺少环境、账号授权或上游接口不可用时，记录未完成项，不将模拟结果称为实机通过。

实现时运行项目约定检查：Rust 格式检查、NSH 检查，交互变更运行 NSH 测试；纯 Rust 逻辑测试按需执行。当前仅编写规格，不宣称已执行任何业务测试。

## Out of Scope

- 国际服、渠道服，以及第一期 Android 客户端实现。
- 密码和短信登录、批量签到、启动器关闭期间定时签到。
- 自有登录账号体系、云同步、登录凭据跨电脑迁移。
- 游戏运行时切换账号或自动强制结束游戏。
- 修改服务器上的成就、武器、圣遗物或材料数量。
- UIGF v3 及以下和旧版 UIAF、其他游戏数据处理、参考工具私有格式兼容。
- 镜像加速、任意第三方商店源、第三方扩展启动器页面的开发框架。
- 自行开发 UnlockerIsland 内部新功能或保证上游模块永久兼容。
- 将未核实的背包自动获取、插件格式或一次扫码覆盖全部服务作为已验证能力。
