## Problem Statement

已配置好游戏目录的玩家打开 Windows 启动器时，要经过账号、UID 数据空间和目录设置才能找到「普通启动」。第一次使用的玩家又需要在同一页判断该选择已有游戏还是下载安装。账号授权、社区签到和本地角色资料并排列出，也让人难以判断眼前的操作会影响哪个账号或 UID。

## Solution

Windows 国服官服启动器按用户任务提供固定左侧导航，依次为「首页」「游戏管理」「米游社」「角色资料」。首页回答“现在能否启动游戏”，游戏管理负责目录和下载，米游社围绕唯一已授权的米哈游账号展示签到，角色资料围绕当前选中的游戏 UID 展示本地记录。用户可以在账号 A 自动签到期间查看 UID B 的资料，也可以直接普通启动游戏。

## User Stories

1. 作为已安装游戏的玩家，我希望打开首页就能普通启动，以便直接进入官方游戏客户端。
2. 作为小窗口用户，我希望缩窄窗口后仍看得到主操作，以便无需横向滚动就能启动。
3. 作为首次使用者，我希望看到唯一候选目录的完整路径，以便确认磁盘和位置后将其设为默认。
4. 作为有多份安装的玩家，我希望从候选目录中选择并确认一项，以便启动正确的副本。
5. 作为未找到游戏的玩家，我希望同时看到「选择已有游戏」和「下载安装」，以便按本机实际情况继续。
6. 作为移动过游戏的玩家，我希望能重新查找、浏览文件夹或手动输入路径，以便恢复有效的默认目录。
7. 作为下载游戏的玩家，我希望在游戏管理页看到目标目录、进度和暂停或继续操作，以便管理当前任务。
8. 作为等待下载的玩家，我希望浏览角色资料时也能看到进度，以便点击侧栏直接回到当前任务。
9. 作为下载中断的玩家，我希望看到失败提示且仍停留在正在阅读的页面，以便自行选择何时查看原因并恢复。
10. 作为未授权的玩家，我希望在米游社页内扫码并看到等待确认、过期、刷新和取消状态，以便完成首次授权。
11. 作为已授权的玩家，我希望打开米游社页先看到当前账号、今日签到结果和奖励日历，以便知道谁已签到、奖励是否到账。
12. 作为需要处理签到异常的玩家，我希望在结果旁检查奖励领取、重试签到或重新扫码，以便直接处理当前问题。
13. 作为正在续期的玩家，我希望看到目标账号，扫错时收到使用原账号的提示，以便重试期间保有原授权和 UID。
14. 作为更换米游社账号的玩家，我希望在管理授权中核对要移除的账号及其影响，以便保留角色资料并按需重新授权。
15. 作为未扫码的玩家，我希望创建和切换本地 UID 数据空间，以便独立管理游戏角色的资料。
16. 作为查看多个游戏角色的玩家，我希望在标题旁切换 UID 后停留在同一资料页签，以便比较同一类记录。
17. 作为查看空数据空间的玩家，我希望看到属于当前 UID 和资料类型的空状态及可用操作，以便知道如何添加第一条记录。
18. 作为清理资料的玩家，我希望在确认前看到完整 UID 和跨类别删除范围，并能用键盘取消，以免误删记录。
19. 作为持续使用启动器的玩家，我希望更新修复、角色资料类型和扩展功能在交付时出现在对应分类，以便从熟悉的位置找到它们。

## Implementation Decisions

| 页面 | 进入页面后看到什么 | 操作与状态变化 |
| --- | --- | --- |
| 首页 | 左侧纯色区放游戏名称、状态和主操作，右侧为提瓦特风格风景图。窄窗口优先裁切风景。 | 默认目录有效时突出「普通启动」，「管理游戏」进入游戏管理页。首次找到一个目录时显示完整路径，多个时列出供选择，确认保存成功后原位置出现「普通启动」。未发现目录时并列提供目录选择和安装位置选择。有下载任务时显示进度及适用的暂停或继续操作。 |
| 游戏管理 | 已安装时页首显示当前目录。「更换目录」展开自动查找、浏览文件夹和手动输入。有下载任务时页首先展示该任务。 | 展示目标目录、进度和适用操作。固定侧栏底部同步显示任务状态，点击直达任务。中断时原位显示「下载中断 · 查看原因」，保持当前页面。 |
| 米游社 | 未授权时首屏提供「扫码添加米哈游账号」。已授权时页头显示当前账号，首屏展示今日社区签到结果和奖励日历。 | 「检查奖励领取」「重试社区签到」「重新扫码」按实际结果就近显示。「管理授权」收纳日常检查和移除操作。添加和续期均在页内展开二维码；扫码后等待手机确认，过期后原位刷新，取消后回到扫码前的状态。 |
| 角色资料 | 标题旁显示 UID 切换器，支持创建数据空间。下方按已交付的资料类型组织页签。 | 切换 UID 后保留当前页签，立即更新记录，空状态标明资料类型并给出适用操作。「资料管理」内提供当前 UID 的删除历史记录入口。 |

- 继续使用 Rust 原生启动器入口。侧栏和工具页沿用首页强调色，路径、日历和记录表采用紧凑布局。跨页共享同一下载任务和签到结果，切页后继续执行既有任务。
- 普通启动沿用启动前的目录校验与系统结果，游戏登录由官方客户端完成。选择角色资料的 UID 只改变浏览对象。米游社授权的归属须经验证，同一时间最多保存一个账号，续期取消、失败或扫错账号时保留原授权。
- **移除账号**从「米游社 → 管理授权」进入。确认框显示实际账号，说明自动签到需重新授权、本地角色资料保留。确认按钮带账号标识。
- **删除历史记录**从「角色资料 → 当前 UID 的资料管理」进入。确认框和确认按钮均显示完整目标 UID，明确删除该 UID 所有类别的本地历史。执行后保留该 UID 数据空间、其他 UID 的记录及米游社授权。两种确认框均默认聚焦「取消」。
- 按一期完整范围分类，入口随功能交付开放。更新、预下载、校验与修复归入游戏管理。抽卡记录与统计、成就进度、背包仓库、养成计划及相关导入导出、备份迁移归入角色资料。插件商店和插件管理交付后增加「扩展」导航。
- 复用现有目录设置、单个米游社授权和按 UID 隔离的本机存储。已有用户重开后继续恢复默认目录、账号、选中的 UID 和可续传任务。

## Testing Decisions

以真实 Rust 启动器界面为统一交互测试入口，沿用现有 NSH 隔离环境控制目录发现、系统启动、下载、扫码和签到返回值。通过用户点击、可见文案、可用操作和重新打开后的结果断言行为。现有交互套件已有默认目录恢复、暂停后重开、扫码续期失败保留原授权、奖励待确认及 UID 历史隔离等用例；迁移这些用例到对应导航路径。

| 验收场景 | 可观察的通过条件 |
| --- | --- |
| 首页与首次设置 | 覆盖有效默认目录及零、一、多个候选。正确保存后主操作变为普通启动，保存或启动失败显示对应结果。没有米游社授权时也能普通启动。 |
| 跨页下载 | 从首页开始安装，切到角色资料后侧栏继续更新。点击进度返回同一任务，暂停、继续、中断及重开后的状态正确。失败提示不强制跳页。 |
| 米游社授权与签到 | 覆盖首次扫码、过期刷新、取消、同账号续期、异账号被拒，以及签到失败重试和奖励待确认。核对账号、原位反馈和恢复结果。 |
| UID 与数据范围 | 未授权也能创建和切换空间。用账号 A 签到时切到 UID B，签到对象仍为 A。多个资料页签交付后验证保留页签和对应空状态。 |
| 两种清理操作 | 取消后数据完整。移除账号后角色资料可查；删除 B 的历史后 B 空间仍可用，A 的记录和授权仍可访问。 |
| Windows 实机 | 核对正常及窄窗口下的布局、风景裁切、主操作可见性和完整路径可辨识性。用键盘打开两种确认框，验证初始焦点为「取消」，默认回车不会执行删除。 |

## Out of Scope

本次交付为 Windows 原生界面改版。后续规划功能的业务实现仍由相应一期任务交付。Android 界面、云同步、游戏客户端内的账号切换以及新增账号或数据存储体系均在本规格范围之外。原型里的演示场景、模拟扫码、虚拟下载和示例导入仅用于评审。

## Further Notes

一期功能范围见 #1，单个米游社授权及续期规则以 #30 为准。可点击原型用于复现与评审页面流程；正式交付以本规格列出的原生界面行为和 Windows 验收结果为准。
