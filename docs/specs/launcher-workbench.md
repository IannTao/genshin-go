## Problem Statement

玩家在 Windows 启动器里查祈愿、看背包或迁移数据时，需要记住哪些工具藏在「角色资料」里。查看背包后转到养成计划，还得确认眼前的材料属于哪个游戏 UID。下载、扫码、导入或恢复进行到一半时，玩家需要看得出任务进度、操作对象，以及取消后会回到哪里。

## Solution

Windows 国服官服启动器采用九入口工作台。侧栏主区依次为「首页」「游戏管理」「米游社」「角色资料」「祈愿分析」「背包仓库」「成就管理」「扩展」，底部固定「系统设置」。首页保留普通启动，三个数据浏览页面可以直接进入，跨 UID 的整体备份与恢复归入系统设置。页面标题、选中页签、完整 UID 和任务反馈共同说明当前上下文。

## User Stories

1. 作为已有安装的玩家，我希望打开首页就能看到普通启动，以便直接进入官方客户端登录。
2. 作为首次使用者，我希望没有候选时可以选择已有游戏或下载安装，只有一个候选时能核对完整路径，有多个候选时能自己选择，以便保存正确的默认目录。
3. 作为移动过游戏的玩家，我希望在「游戏管理」重新查找、浏览或输入目录，以便看到校验结果，在保存失败后仍能找回原配置。
4. 作为下载游戏的玩家，我希望看到安装位置、字节数、百分比及暂停和继续操作，以便掌握正式版与中文语音包的安装进度。
5. 作为边下载边整理资料的玩家，我希望在其他页面也能看到进度，点击后回到同一任务，以便下载中断时由我决定何时处理，重开后能手动继续。
6. 作为常用多个工具的玩家，我希望从侧栏一步打开祈愿、背包、成就或设置，以便在每页都能从标题和高亮项辨认位置。
7. 作为小窗口用户，我希望收起侧栏后内容区随之变宽，图标仍有名称提示和任务指示，以便看清数据、启动按钮以及可换行的完整路径。
8. 作为切换主题的玩家，我希望在顶栏或「系统设置 → 外观」切换深浅主题和侧栏形态，以便翻页时延续同一外观。
9. 作为桌面用户，我希望最小化后恢复原页面和尺寸状态，能用按钮或双击顶栏空白处最大化和还原，以便暂时离开再接着操作。关闭后重新打开时，从普通尺寸的首页开始。
10. 作为键盘用户，我希望按阅读顺序移动焦点，打开确认框后焦点留在框内，按 Esc 关闭后回到触发处，以便安全地完成操作。
11. 作为米游社用户，我希望在同一页扫码、确认、刷新过期码、取消或检查授权，以便看到唯一米哈游账号及其经验证的游戏 UID。
12. 作为续期授权的玩家，我希望扫错账号时看到原因并保留原授权，更换账号时明确确认移除对象，以便知道自动签到何时暂停。
13. 作为查看签到的玩家，我希望看到近七个北京日期的结果，辨别「未检查」、签到失败、奖励待确认与已领取数量，以便就地重试签到、检查奖励或重新扫码。
14. 作为管理多个游戏 UID 的玩家，我希望未授权时也能创建 9 至 10 位 UID 数据空间，在资料页签内切换 UID 后立即看到对应数据，以便在相同视图比较记录。重开时恢复上次选中的 UID。
15. 作为刚建立数据空间的玩家，我希望空页面写明完整 UID、资料类型和可执行的下一步，以便知道该导入文件、同步角色还是创建计划。
16. 作为查看角色的玩家，我希望在「角色资料」切换「已拥有角色」和「养成计划」，看到角色元素形态、等级、突破、命座、天赋及数据时间，以便决定接下来培养谁。
17. 作为启用角色同步的玩家，我希望在游戏管理检查并保存扫描设置，启动时可跳过等待、启动后可取消本次同步，也可停用下次同步，以便扫描故障时仍能普通启动并看到各自结果。
18. 作为规划养成的玩家，我希望为角色或武器填写当前与目标等级、突破及适用的天赋，在手填库存与本 UID 的导入库存间切换，以便按采集时间判断缺口并保存计划。
19. 作为查看祈愿的玩家，我希望「总览」并排显示各卡池统计，「历史」「角色」「武器」可按卡池和关键词筛选，以便找到记录并看懂共享保底、稀有度分布和距上次四星、五星的抽数。
20. 作为交换祈愿记录的玩家，我希望选择 UIGF 文件中的原神记录组、核对目标 UID、预览重复与冲突，再确认导入或取消，以便回到祈愿页核对结果，也能导出记录。
21. 作为查看背包的玩家，我希望在武器、圣遗物、材料之间切换，用名称、类型、品质查找物品，并按品质、名称或适用的等级、数量排序，以便找到当前或历史快照里的物品及其采集时间。
22. 作为导入背包的玩家，我希望明确文件覆盖哪些类别，并区分「没有提供材料」与「材料库存为空」，以便部分导入时保留其他类别的库存。
23. 作为已授权的玩家，我希望在绑定 UID 的背包中同步米游社培养材料，以便直接用新材料快照计算缺口，武器和圣遗物仍可独立查看。
24. 作为维护成就的玩家，我希望按分类查看完成数，按名称、描述、ID、版本和完成状态筛选，展开阶段与目标值，以便勾选或取消后马上看到进度和统计更新。
25. 作为交换成就记录的玩家，我希望预览 UIAF 文件将新增、更新、重复或冲突的记录，并在缺少 UID 时显式选择归属，以便合并后查看和导出含目录外 ID 的结果。
26. 作为换电脑的玩家，我希望在「系统设置 → 备份与恢复」创建整体备份、选择文件、逐 UID 预览差异，以便在确认前为冲突的养成计划和手填库存逐项选择保留版本。
27. 作为执行导入或恢复的玩家，我希望取消后回到所属模块，确认后看到实际写入结果和操作前的备份位置，以便核对数据并能找回操作前的记录。
28. 作为清理资料的玩家，我希望「移除账号」和「删除历史记录」分别显示完整账号或目标 UID、影响范围，并默认聚焦「取消」，以便只清理我选中的对象。
29. 作为管理扩展的玩家，我希望看到精选插件的来源、版本、权限、许可、风险与安装状态，能重新加载目录、安装、手动更新和卸载，以便决定是否使用该扩展。

## Implementation Decisions

- 沿用 Rust 根组件与现有业务模块。工作台负责导航、当前页签、外观和跨页任务入口。祈愿、背包、成就和备份各自沿用现有读写规则。#34 的四页导航由上述九入口顺序接续，首页启动和 #35 至 #40 已定义的跨页行为继续作为回归依据。
- 顶栏左侧放侧栏开关和 Genshin Go 名称，右侧放主题切换与 Windows 窗口控件。页面标题在内容区。侧栏展开宽 212 px，收起宽 72 px，系统设置用分隔线与主区区分。窄窗口优先裁切首页右侧风景，数据页随可用宽度重排。
- 下载任务按安装目录持续存在。切页、折叠侧栏和打开资料不会创建新任务。中断就地说明原因，重开等待手动继续，安装成功后设置默认目录。启动前重验目录；启动结果表明 Windows 是否接受了请求。
- 分别处理当前浏览 UID、米游社授权账号、实际游戏登录 UID 和本次导入目标 UID。在本机 SQLite 保存 UID 资料，Windows 当前用户的 DPAPI 保护授权凭据。整体备份只携带业务数据。自动签到在启动器打开、北京跨日和系统唤醒时检查当天未完成项；签到重试和奖励查询分别处理。
- 启动同步沿用 #41 的设置与提示。可复用已运行的服务或启动专用实例，准备超过 15 秒后继续启动游戏。游戏启动结果与扫描结果分行显示；跳过或取消只影响本次同步。所得角色归档到实际登录 UID，浏览位置随玩家选择。
- 文件操作按「选择文件 → 核对归属及适用的时间、类别 → 预览 → 确认并先备份 → 显示写入结果与备份路径」进行。预览和取消均不写入。祈愿、成就、背包各自返回所属模块；整体恢复返回设置中的「备份与恢复」页签。
- 祈愿读取 UIGF v4.0 至 v4.2，提示跳过其他游戏数据，按记录 ID 去重，冲突保留本机，导出 v4.2。总览说明集录与溯光共享保底，历史缺失时标明可确定的统计范围。
- 成就沿用离线简体中文目录。手动标记保留已有进度数值，展示完成时间及来源，缺失时显示「完成时间未知」。UIAF v1.1 合并取较强状态、较大进度和已完成记录最早的已知时间。
- 背包沿用 GOOD v1 至 v3。核对归属、原始采集时间和时区，按文件覆盖的类别写入。缺失类别需经玩家明确确认才可作为空库存。各类别默认读取本 UID 最新可用快照，回看旧快照保留当时的时间和内容。米游社同步只写材料快照。养成计划共享同 UID 手填库存，导入库存只读，显示快照时间并按现有养成规则计算缺口。
- 整体备份写出 v2，恢复兼容 v1 和 v2。逐 UID 展示新增、重复、冲突及新建空间。祈愿和成就沿用各自合并规则，同采集时间的背包快照冲突保留本机；冲突的计划和手填数量须逐项选择后方可确认。旧版缺少的类别保留现有数据。
- 两种危险操作分别确认。移除授权会暂停该账号自动签到，UID 资料继续可用。删除历史时确认框及按钮均带完整 UID，清理该 UID 的祈愿、成就、已拥有角色、背包、计划与手填库存，保留其空间、其他 UID、备份与导出文件及授权。
- 「扩展」沿用项目维护的目录、受管安装位置和内容摘要校验。插件详情提供核实版本、来源、所需文件和权限；加载失败提供重试，缺少文件提供重新安装。

## Testing Decisions

- 主入口为 Windows 启动器的 Rust 根组件。沿用 NSH 行为测试，通过玩家能按的按钮、能读到的状态、返回的位置和重开后的数据断言结果。已有「导入背包后在养成计划读取库存」「扫描准备期间直接启动」用例可作为跨页与异步流程的先例。
- 从首页依次访问九个入口，核对顺序、底部设置、页标题与选中项。切换深浅主题及两种侧栏形态后跨页，检查主区宽度、图标提示与下载指示。对照评审稿，在窄窗检查主操作可达、长路径可读。
- 从背包向 UID A 导入仅含材料的文件，在角色养成页读取采集时间及缺口，原装备仍可查看。在同一页签切到 UID B，核对 B 的数据或具名空状态；重开确认上次 UID。对祈愿筛选、成就标记和历史快照也通过页面操作验证。
- 分别从祈愿、成就、背包和系统设置打开预览。先取消，核对原页签与原数据；再次进入并确认，核对目标 UID、备份路径、合并结果与重开后的数据。用含冲突的整体备份验证必须完成逐项选择，用 v1 备份验证已有计划和快照仍可读。
- 用现有受控安装目录、下载和扫描场景验证零至多个候选、保存失败、下载跨页中断、手动继续，以及跳过、超时或取消扫描后游戏只启动一次。授权续期失败、奖励待确认、移除授权和删除历史分别从对应页面验证影响对象。
- Windows 实机补验最小化还原、双击顶栏、最大化、关闭重开、系统文件选择器、键盘顺序、对话框焦点限制与归还。分别用 Enter 和 Esc 验证危险操作默认取消。HTML 的 27 个画板提供布局与状态对照；原生实现的验收记录需来自启动器本身。

## Out of Scope

- 增量更新、预下载和校验修复由 #8、#9、#10 跟踪。后续接入沿用跨页任务入口，区分下载资源和应用修改，并在目录占用时说明普通启动的等待原因。
- 已拥有角色的启动同步已有入口；武器、圣遗物、成就的分批到达、完整类别替换及四类恢复由 #41 至 #47 跟踪。可选扩展启动由 #27、#28 跟踪，Windows 构建与干净环境发布验收由 #29 跟踪。
- HTML 的「⋯」画板跳转、重置演示、浏览器内模拟任务栏及样例文件路径仅用于设计评审。游戏签到、云游戏签到、批量签到、云同步、镜像加速、任意第三方商店源和 Android 伴随端均在本次范围之外。

## Further Notes

本规格依据《Genshin Go · Windows 功能与交互清单》和配套可点击评审稿。九入口布局与页面返回路径采用评审稿；清单中的「已有入口」指本地业务已有接入，原生导航核对时为六项。#1 记录一期范围，#30 记录单账号授权，#34 记录前一版导航，#41 记录分类同步。规划项的交付状态由各自 Issue 单独验收。
